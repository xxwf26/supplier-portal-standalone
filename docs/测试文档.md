# 画师资源库系统 — 测试文档

> 适用版本：supplier-portal-standalone（React 19 + NestJS 10 + MySQL + Drizzle）
> 端口约定：后端 `localhost:3001`（`.env` 实际值），前端 dev `localhost:5174`（vite 实际值）
> 测试账号：管理员 `admin/admin123`，仅查看 `viewer/viewer123`

---

## 0. 测试环境准备

| 步骤 | 操作 | 预期 |
|------|------|------|
| 0.1 | 创建数据库 `supplier_portal`（utf8mb4） | 成功 |
| 0.2 | `cd server && npm i && npm run db:generate && npm run db:migrate` | 生成并执行迁移，建出 `suppliers`/`audit_log`/`filter_config` 表 |
| 0.3 | `npm run start:dev` | 控制台输出 `Server running on http://0.0.0.0:3001` |
| 0.4 | `cd client && npm i && npm run dev` | 打开 `http://localhost:5174` |
| 0.5 | 确认 `mysqldump` 在 PATH 中（快照功能依赖） | `mysqldump --version` 有输出 |

> ⚠️ 当前没有自动化测试框架（无 jest/vitest）。本文档以**手工 + 接口测试**为主，并在末尾给出建议补充的自动化用例。

## 2. 鉴权与权限（P0）

### 2.1 登录
| 用例 | 步骤 | 预期 |
|------|------|------|
| 正常登录 | 输入 admin/admin123 → 登录 | 进入看板，右上角显示管理员操作（导入/新建/历史） |
| 错误密码 | admin/wrong | toast「用户名或密码错误」，停留登录页 |
| 空字段 | 用户名或密码留空 → 提交 | 不发请求（按钮无响应） |
| viewer 登录 | viewer/viewer123 | 进入看板，**看不到**导入/新建/历史/编辑按钮 |

### 2.2 记住我 / Token 时效
| 用例 | 步骤 | 预期 |
|------|------|------|
| 勾选记住我 | 登录时勾选 → 提示「有效期 30 天」 | 下次打开自动回填用户名 |
| 不记住 | 不勾选 → 提示「有效期 8 小时」 | 下次打开不回填用户名 |
| Token 过期 | 手工把 localStorage `auth.token` 改成过期 token，刷新 | 自动登出回到登录页 |
| 401 拦截 | 删除/篡改 token 后调用受保护接口 | 前端清除 auth 并刷新页面 |

### 2.3 角色越权（重点）
| 用例 | 步骤 | 预期 |
|------|------|------|
| viewer 调写接口 | 用 viewer 的 token 直接 `POST /api/suppliers` | **403** 拒绝 |
| 无 token 调写接口 | 不带 Authorization `POST /api/suppliers` | **401** |
| 无 token 读列表 | `GET /api/suppliers`（无 token） | 200（读接口未鉴权，确认是否符合预期） |
| viewer 调配置写接口 | `POST /api/config/filters`（viewer token） | 403 |

## 3. 供应商 CRUD（P0）

### 3.1 新建
| 用例 | 步骤 | 预期 |
|------|------|------|
| 必填校验 | 名称留空提交 | 400「账号名称不能为空」 |
| 最小新建 | 仅填名称提交 | 成功，列表出现该画师，默认 `风险状态=暂无`、`库内=是` |
| 全字段新建 | 填报价项/社媒链接/联系方式/合同信息 | 详情页字段完整回显 |
| 备注超长 | 备注输入 >500 字 | 实时字数提示，后端截断为 500 |
| 报价项多条 | 添加多个报价（类型+单价+单位） | 卡片/详情正确展示，价格区间取 min~max |

### 3.2 编辑
| 用例 | 步骤 | 预期 |
|------|------|------|
| 局部更新 | 只改评分 | 其它字段不变，`updatedAt` 刷新 |
| 清空字段 | 把已有报价/联系方式清空保存 | 详情页对应字段为空 |
| 合同到期日 | 设置/清除日期 | 正确存储与回显（注意时区） |
| 手动链接 | 补录 manualLinks | 卡片链接区合并展示 social+manual |

### 3.3 删除
| 用例 | 步骤 | 预期 |
|------|------|------|
| 正常删除 | 详情页删除 → 确认 | 列表移除，历史里出现 DELETE 记录 |
| 删除不存在 id | `DELETE /api/suppliers/不存在id` | **见 Bug #8：当前恒返回 success，应返回 404** |

## 4. 列表 / 筛选 / 排序（P0）

> ⚠️ 当前实现：前端一次性拉取**全部**数据，所有筛选/搜索/排序均在浏览器端完成，后端筛选参数未被使用。数据量大时需重点测性能。

### 4.1 筛选
| 用例 | 步骤 | 预期 |
|------|------|------|
| 单类型筛选 | 勾选「个人」 | 仅显示个人画师，计数同步 |
| 多条件叠加 | 类型+风格+状态同时勾选 | 取交集 |
| 风格分词 | 画师风格为「日系/古风」 | 勾选「古风」能命中（按 `/、，` 分词） |
| 清空筛选 | 点「清空筛选」 | 恢复全部，slider 回到 500~10000 |
| 报价区间 ⚠️ | **见 Bug #6**：报价 <500 或 >10000 的画师 | 当前会被**永久隐藏**，即使没动滑块 |
| 报价边界 | 画师报价 500 / 10000 | 应被包含 |
| 无报价 | 画师无任何价格 | 不受报价筛选影响（始终显示） |

### 4.2 关键词搜索
| 用例 | 步骤 | 预期 |
|------|------|------|
| 名称搜索 | 输入画师名片段 | 命中 |
| 备注搜索 | 输入备注中的词 | 命中（仅搜名称+备注，不含风格/项目） |
| 繁简互通 | 数据存「繪師」，搜「绘师」 | 命中（前端 OpenCC 归一化） |
| 大小写 | 英文名大小写混合 | 命中（已 toLowerCase） |
| 空格 | 前后空格 | 自动 trim |

### 4.3 排序
| 用例 | 预期 |
|------|------|
| 评分高→低 | 无评分排最后 |
| 评分低→高 | 无评分排最后（Infinity 处理） |
| 频次升/降 | 数值正确 |
| 最近更新 | 按 updatedAt 降序 |

## 5. Excel 导入（P0，重点模块）

### 5.1 文件解析
| 用例 | 步骤 | 预期 |
|------|------|------|
| 正常 xlsx | 含「名称/供应商类型/报价」表头 | 进入预览，识别字段数正确 |
| 拖拽上传 | 拖入 xlsx | 同点击上传 |
| 非 Excel | 拖入 .txt/.png | 提示格式错误 |
| 空文件 | 0 行数据 | 「Excel 文件中没有数据」 |
| 超量 | >500 行 | 「单次导入最多 500 条」 |
| 无可识别列 | 表头全是无关字段 | 「无法识别任何列…」 |
| 缺名称列 | 有其它列但无「名称」 | 「未找到名称列…」 |
| 表头别名 | 用「账号名」「类型」「频次」 | 能映射到正确字段 |

### 5.2 预览与映射
| 用例 | 预期 |
|------|------|
| 翻页 | 每页 20 条，上/下页按钮在边界禁用 |
| 字段转换 | 频次/评分转数字，「是/否」转布尔，社媒列合并为 socialLinks |
| 二次确认 | 点「确认导入」弹二次确认框 |

### 5.3 写入与回执
| 用例 | 预期 |
|------|------|
| 全部成功 | 绿色「导入成功」，列表刷新出现新数据 |
| 部分失败 | 黄色「部分失败」，列出失败行号+原因 |
| 导入后历史 ⚠️ | **见 Bug #2**：导入的数据 `importSource` 仍为 manual、无 `importBatchId`，导致「导入批次/回滚」功能失效 |
| 同秒批量 ⚠️ | **见 Bug #1**：批量插入时审计日志的 newData/recordId 可能错位 |

## 6. 导入历史 / 回滚 / 快照（P1）

| 用例 | 步骤 | 预期 |
|------|------|------|
| 变更日志列表 | 打开「历史」面板 | 分页显示 INSERT/UPDATE/DELETE 记录 |
| 单条撤回-新增 | 撤回一条 INSERT | 对应供应商被删除 |
| 单条撤回-更新 | 撤回一条 UPDATE | 字段恢复为旧值（注意 contractDeadline 日期还原） |
| 单条撤回-删除 | 撤回一条 DELETE | 供应商被重新插入 |
| 批次列表 ⚠️ | 查看导入批次 | **见 Bug #2/#3：因 importBatchId 从未写入，列表恒为空，回滚不可用** |
| 创建快照 | 管理员点创建快照 | `backups/` 下生成 `.sql`，依赖 mysqldump |
| 快照清理 | 超过 30 个快照 | 自动删除最旧的 |
| 快照失败 | mysqldump 不在 PATH | 友好报错，不影响主流程 |

## 11. 安全测试清单（建议）

- [ ] JWT 密钥硬编码且入库（见 Bug #5）— 生产应走环境变量、随机化
- [ ] 默认弱口令 admin/admin123（见 Bug #4）
- [ ] 服务绑定 0.0.0.0 暴露局域网（见 Bug #4）
- [ ] 未知异常向客户端返回 stack/cause（见 Bug #7）— 信息泄露
- [ ] 上传仅校验可伪造的 mimetype（见 Bug #10）
- [ ] 无全局 ValidationPipe，DTO 未做类型/长度校验（见 Bug #11）
- [ ] 读接口（列表/详情/统计）无鉴权，确认是否符合数据敏感级别

## 12. 建议补充的自动化测试

服务端（建议引入 Jest + supertest）：
- `auth.service.spec`：validateUser 正确/错误分支
- `supplier.service.spec`：create 返回值正确性、update 部分字段、findAll 各筛选条件
- `audit.service.spec`：rollbackBatch 原子性、rollbackLog 三种操作还原
- e2e：登录→建→改→删→历史→撤回 全链路；角色 403/401

前端（建议 Vitest + Testing Library）：
- `processSupplier` 价格/状态/链接推导
- `chineseNormalize` 繁简归一
- 报价区间筛选逻辑（覆盖 Bug #6 场景）
- ExcelImportModal 的 `mapRow` 字段映射
